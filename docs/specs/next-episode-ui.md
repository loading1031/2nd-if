# 다음 화 선택 UI 및 가중치 정렬

> 기획 문서

## 상태: 기획 중

## 개요
독자가 한 화를 다 읽고 "다음 화"로 넘어가는 시점에, 원작 다음 화 + 2차 창작 분기들을 가중치 순으로 보여주는 핵심 UI.

## 표시 구조

```
┌─────────────────────────────────┐
│  [원작] 제31화: 원작 제목        │  ← 항상 최상단 고정
│  by 원작자  ♥ 1,234  👁 5,678   │
├─────────────────────────────────┤
│  [분기] 제31화: 다른 결말        │  ← engagement_score 순 정렬
│  by 2차작가A  ♥ 456  👁 2,100   │
├─────────────────────────────────┤
│  [분기] 제31화: 만약 그때...     │
│  by 2차작가B  ♥ 123  👁 890     │
├─────────────────────────────────┤
│  [분기] 제31화: 히든 엔딩        │
│  by 2차작가C  ♥ 45   👁 320     │
└─────────────────────────────────┘
│                                 │
│    + 여기서 새 분기 만들기       │  ← 분기 생성 버튼 (조건 충족 시)
└─────────────────────────────────┘
```

## 정렬 규칙
1. **원작 다음 화**: 항상 최상단 고정 (is_original = true)
2. **2차 창작 분기**: engagement_score 내림차순
3. 분기가 없으면 원작 다음 화만 표시 (일반 소설 읽기와 동일)

## engagement_score 계산

```
engagement_score = (visit_count × 1.0) + (like_count × 3.0)
```

- `visit_count`: 이 경로로 실제 이동한 횟수 (클릭)
- `like_count`: 해당 에피소드에 달린 좋아요 수
- 가중치 비율은 추후 조정 가능

## 가중치 업데이트 시점
- **visit_count**: 독자가 해당 "다음 화" 항목을 클릭하여 이동할 때 +1
- **like_count**: 에피소드 내에서 좋아요 버튼 클릭 시 +1 (토글)

## 표시 조건
- 분기점은 해당 에피소드까지 모두 읽은 독자에게만 표시
- 미읽은 독자에게는 원작 다음 화만 자동 연결 (스포일러 방지)

## 카드 표시 정보
| 항목 | 설명 |
|------|------|
| 라벨 | [원작] 또는 [분기] |
| 에피소드 번호 | 분기 시작점 기준 화 번호 |
| 제목 | 에피소드 제목 |
| 작성자 | by {닉네임} |
| 좋아요 수 | ♥ {like_count} |
| 이동 횟수 | 👁 {visit_count} |

## HTMX 구현 방향
- 에피소드 본문 하단에 다음 화 선택 영역
- `hx-get`으로 다음 화 목록 로드 (Neo4j에서 가중치 순 조회)
- 다음 화 클릭 시 `hx-post`로 visit_count 업데이트 + 페이지 이동

- [[auth]] — 읽기 이력 확인 (스포일러 방지)
