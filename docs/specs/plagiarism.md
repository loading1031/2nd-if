# 표절 검사

> 기획 문서

## 상태: 기획 중 (MVP 이후)

## 개요
분기 생성 시 원작과의 유사도를 자동 검사하여, 원작 스포일러 및 표절을 방지하는 시스템.

## 검사 대상

### 1. 원작 대비 유사도 (분기 생성 시)
- 분기 에피소드가 원작의 이후 전개와 지나치게 유사한 경우 감지
- 목적: 원작 스포일러 방지 + 단순 복붙 차단

### 2. 다른 작품 대비 유사도 (신고 기반)
- 다른 플랫폼/작품의 내용을 그대로 가져온 경우
- 자동 검사가 아닌 [[moderation]] 신고 시스템을 통해 처리

## 자동 검사 플로우

```
분기 에피소드 발행 요청
    ↓
원작의 이후 에피소드들과 유사도 검사
    ↓
유사도 < 원작자 설정 기준% → 바로 게시
유사도 ≥ 원작자 설정 기준% → 원작자 승인 대기
    ↓
원작자 승인 → 게시 (이후 저작권 신고 대상에서 제외)
원작자 거절 → 게시 불가 (사유 안내)
원작자 무응답 (N일) → 자동 게시 or 보류 (정책 결정 필요)
```

## 원작자 설정

| 설정 | 설명 |
|------|------|
| 유사도 기준 (%) | 이 수치 이상이면 승인 필요 (기본값: 70%) |
| 자동 승인 | 유사도 검사 없이 모든 분기 허용 |
| 전체 차단 | 라이선스 "분기 금지"와 동일 효과 |

- 원작자가 직접 분기를 만드는 경우 검사 생략
- 한번 승인된 작품은 저작권 관련 신고 대상에서 제외

## 유사도 측정 기술 (후보)

| 방법 | 설명 | 적합성 |
|------|------|--------|
| 코사인 유사도 (TF-IDF) | 단어 빈도 기반 | 단순하지만 문맥 무시 |
| 문장 임베딩 비교 | BERT/Sentence-BERT | 문맥 이해, 비용 높음 |
| n-gram 매칭 | 연속 단어 겹침 비교 | 직접 복붙 감지에 강함 |
| 하이브리드 | n-gram + 임베딩 | 가장 정확, 구현 복잡 |

- MVP 이후 구현이므로 기술 선택은 추후 확정
- 초기에는 n-gram 매칭으로 시작, 이후 고도화

## 데이터 모델

### 유사도 검사 결과 (Django ORM)
| 필드 | 타입 | 설명 |
|------|------|------|
| branch_episode | Episode | 검사 대상 분기 에피소드 |
| original_episode | Episode | 비교 대상 원작 에피소드 |
| similarity_score | float | 유사도 (0.0 ~ 1.0) |
| status | enum | pending / approved / rejected |
| reviewed_by | User | 승인/거절한 원작자 (null=미검토) |
| reviewed_at | datetime | 검토 시점 |
| created_at | datetime | 검사 시점 |

## 의존성
- [[branch]] — 분기 생성 시 검사 트리거
- [[story]] — 원작 에피소드와 비교
- [[license]] — 원작자 설정과 연동
- [[auth]] — 원작자 승인/거절 권한
- [[moderation]] — 외부 작품 표절은 신고로 처리
