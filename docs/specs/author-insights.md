# 작가 독서 인사이트

- 작성일: 2026-10-16
- 상태: 초안 (핵심 지표·권한 결정 반영)
- 관계: [platform.md](platform.md)의 작가 인사이트 상세. 관련 문서: [story.md](story.md), [branch.md](branch.md)

## 결론

작가에게 독자의 읽기 흐름을 설명하는 관찰 지표를 제공한다. GA4로 서비스 행동 이벤트를 수집하고 BigQuery까지 내보내며, 작품 공개 여부와 별도로 작가가 지표 공개 범위를 설정한다.

## 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 이탈 | 읽기 시작 시각부터 24시간 후, 독자의 마지막 페이지가 해당 회차의 마지막 페이지가 아니면 이탈로 집계한다. 실시간 집계는 필요하지 않다. | 단순하고 일관된 회차 이탈 기준 |
| 페이지 속도 | 각 페이지에서 다음 페이지로 이동하기까지 걸린 시간을 페이지별로 제공한다. 이탈 판정된 독자는 체류 시간 집계에서 제외한다. | 독서 속도를 품질 평가와 분리 |
| 해석 | 빠른 페이지 이동은 빠른 읽기 행동으로만 표시한다. 작품의 좋고 나쁨을 판정하는 점수로 쓰지 않는다. | 행동 지표를 가치 판단으로 오용하지 않음 |
| 지표 권한 | 작품 공개 범위와 별도로 작가가 지표 공개 범위를 `작가만 / 초대한 사람만 / 전체 공개` 중 선택한다. 기본값은 `작가만`이다. 공개 작품도 이 설정으로만 지표를 공유한다. | 콘텐츠 열람 권한과 분석 권한 분리 |
| 최소 표본 | 작가가 공개 범위를 설정하면 현재는 최소 표본 기준으로 지표를 숨기지 않는다. | 공개 정책을 작가 설정에 따름 |
| 분기 소유권 | 분기 내부의 읽기 흐름 지표는 분기 작가에게만 제공한다. 원작 작가에게 분기 자체의 내부 지표는 노출하지 않는다. | 창작물별 분석 소유권 유지 |
| 분기 유입 | 독자가 분기에서 원작 흐름으로 돌아오는 합류 지점은 원작 퍼널에 분기 경유 유입으로 표시한다. | 2차 창작이 원작에 유입을 돌려주는 가치를 공유 |
| 수집·내보내기 | 현재 계획은 GA4 수집과 BigQuery 내보내기까지다. BigQuery 이후 장기 보관·서비스 DB 적재는 후속 범위다. | 초기 분석 경로를 한정 |

## 이벤트와 지표

GA4 자동 이벤트와 서비스 고유 행동을 구분한다. 작가가 GA4를 설정하거나 이벤트를 직접 만들지 않는다. 플랫폼이 공통 규격을 정하고 제품 코드가 계측한다.

| 이벤트 이름 | 수집 기준 | 필수 문맥 매개변수 |
|---|---|---|
| `reader_start` | 회차의 첫 페이지가 실제 표시되어 읽기 시도가 시작됨 | `work_id`, `episode_id`, `page_id`, `reading_run_id`, `source_surface_id`·`component_id`·`placement_id`(내부 유입일 때) |
| `reader_page_view` | 리더 페이지가 독자에게 실제 표시됨. 사전 로드만으로는 보내지 않음 | `work_id`, `episode_id`, `page_id`, `reading_run_id` |
| `reader_page_advance` | 독자가 다음 페이지로 이동함 | `work_id`, `episode_id`, `from_page_id`, `to_page_id`, `elapsed_ms`, `reading_run_id` |
| `reader_episode_navigate` | 독자가 다른 회차로 이동함 | `work_id`, `from_episode_id`, `to_episode_id`, `navigation_type`, `reading_run_id` |
| `reader_branch_select` | 독자가 원작에서 분기를 선택함 | `origin_work_id`, `branch_work_id`, `timeline_item_id` |
| `reader_branch_rejoin` | 분기 독자가 원작 흐름으로 돌아옴 | `origin_work_id`, `branch_work_id`, `destination_episode_id`, `timeline_item_id` |
| `shared_component_impression` | 공용 홈/검색/배너 콘텐츠가 독자 화면에 노출됨 | `source_surface_id`, `component_id`, `placement_id`, `destination_work_id` |
| `internal_content_open` | 독자가 서비스 내부 컴포넌트를 눌러 작품/회차로 이동함 | `source_surface_id`, `component_id`, `placement_id`, `destination_work_id`, `destination_episode_id`(있을 때) |
| `reader_asset_open` | 독자가 본문 표현을 눌러 시각 에셋을 엶 | `work_id`, `episode_id`, `page_id`, `asset_id`, `asset_type` |

`reading_run_id`는 회차별 독서 이벤트를 묶는 임의 식별자다. 구현 제안은 브라우저의 임시 저장소에 회차 ID와 함께 보관하고, 24시간 안의 재방문은 같은 읽기 시도에 연결하며, 판정 시각 이후의 시작은 새 시도로 만드는 방식이다. GA4 세션 구분만으로는 24시간 단위 읽기 시도를 안정적으로 구분하기 어려우므로 별도 값이 필요하다. 계정 간 기기 병합은 하지 않는 권고다.

모든 자체 이벤트는 적용 가능한 경우 `schema_version`을 포함한다. ID는 DB의 안정된 내부 식별자이며 제목, 본문, 검색어, 사용자 이름, 이메일 등 원문·직접 식별정보를 매개변수로 보내지 않는다. 이벤트에는 페이지 경로·제목이 자동 포함될 수 있으므로 GA4에 보내는 URL과 제목에도 개인 정보가 없는지 검토한다.

GA4의 `page_view`는 페이지 로드나 브라우저 history 변경을, 자동 `click`은 기본적으로 외부 도메인 링크 클릭을 수집한다. 따라서 리더가 같은 URL에서 페이지 상태만 바꾸거나 독자가 분기·텍스트 에셋을 선택하는 행위는 위 자체 이벤트로 보내야 한다. 공용 컴포넌트는 노출과 클릭을 각각 보내야 전체 노출 대비 작품 유입 비율을 계산할 수 있다. 노출 판정의 화면 가시성 임계값은 구현 단계에서 정한다.

공용 작품 카드처럼 한 컴포넌트 안에 여러 목적지가 있으면, 각 작품 카드가 화면에 노출될 때 목적지별 impression을 한 번 보낸다. 작가 공용 화면에서는 목적지 ID를 제거해 컴포넌트 전체 노출·클릭·읽기 시작 수와 클릭률만 합산한다. 자기 작품 대시보드에서는 자기 작품으로 들어온 항목만 `component_id`와 `placement_id`별로 나눈다.

### 지표 소유권과 공용 컴포넌트 집계

- 작품·분기 단위 상세 지표는 해당 작품의 작가 권한으로만 제공한다. 다른 작품의 유입·열람 상세값은 노출하지 않는다.
- 공용 컴포넌트의 노출·클릭은 목적지 작품별 결과를 나누지 않은 플랫폼 전체 집계로 모든 작가에게 공유한다.
- 작품 작가는 자기 작품 퍼널에서 어떤 공용 컴포넌트가 자기 작품으로 유입을 보냈는지 볼 수 있다. 다른 목적지 작품의 개별 수치나 순위는 볼 수 없다.
- 원작자는 원작 퍼널에서 분기를 거쳐 원작으로 돌아온 전체 유입 합계를 본다. 분기별 유입 상세와 분기 내부 페이지·이탈 지표는 분기 작가 권한에 남긴다.

### 계산

- **회차 이탈률:** `24시간 판정이 끝난 이탈 독서 시도 수 / 24시간 판정이 끝난 전체 독서 시도 수`로 계산한다. 각 시도는 `독서 시작 시각 + 24시간`에 판정하며, 그 시점의 마지막 표시 페이지가 회차 마지막 페이지가 아니면 이탈이다. 아직 24시간이 지나지 않은 시도는 해당 기간 계산에서 제외한다.
- **페이지 전환 시간:** 페이지가 활성 상태로 표시된 시각부터 다음 페이지 이동까지의 시간이다. 탭/앱이 백그라운드에 있던 시간은 제외한다. 이탈로 분류된 독자의 전환 시간은 집계에서 제외한다. 마지막 페이지는 다음 페이지 전환이 없으므로 전환 시간 지표가 없다.
- **페이지 속도:** 회차 완주자의 페이지별 전환 시간 중앙값과 포함 전환 건수를 보여준다. 이탈 여부 외의 긍정·부정 점수로 환산하지 않는다.
- **분기 유입:** 원작 합류 이벤트를 원작의 퍼널 도착으로 집계한다. 원작 작가에게는 모든 분기를 합산한 유입 총량만 제공하고, 분기별 상세값 및 분기 안쪽의 페이지·이탈 지표는 각 분기 작가 권한으로 유지한다.
- **공용 유입:** `클릭률 = 공용 컴포넌트 클릭 수 / 노출 수`. `읽기 시작률 = 해당 컴포넌트에서 시작된 읽기 수 / 노출 수`. 공용 통계에서는 목적지별 숫자를 분리하지 않는다.

## 권한 흐름

```text
작품 공개 범위 ── 독자가 작품을 읽을 수 있는지 결정
지표 공개 범위 ── 누가 해당 작품의 집계 지표를 볼 수 있는지 결정
분기 내부 지표 ── 분기 작가
분기 → 원작 합류 지표 ── 원작 작가의 원작 퍼널
```

지표 공개 범위는 `작가만`, `초대한 사람만`, `전체 공개` 중에서 작가가 선택하며 기본값은 `작가만`이다. `초대한 사람만`을 선택하면 작가가 서비스 계정으로 초대한 계정만 해당 작품의 집계 지표를 볼 수 있다. 이 초대는 작품 열람 권한이나 편집 권한을 부여하지 않으며, 콘텐츠 접근은 작품의 열람 정책으로 별도 판정한다. 공개 범위가 바뀌거나 초대가 해제되면 다음 요청부터 새 권한으로 검사한다. 최소 표본 숨김은 현재 요구사항에 포함하지 않는다.

작가·초대 사용자의 권한 검사는 GA4나 BigQuery가 아니라 서비스가 수행한다. 대시보드 API는 요청마다 작품 소유자 또는 현재 유효한 초대 여부를 확인하고, 해당 권한으로 제한된 집계만 돌려준다. BigQuery 프로젝트·GA4 속성의 직접 접근 권한은 작가에게 주지 않는다.

### 공개·초대 사용자 흐름 (구현 제안)

1. 작품 설정에서 지표 공개 범위를 `작가만` / `초대한 사람만` / `전체 공개` 중 고른다.
2. `초대한 사람만`이면 서비스 계정을 지정해 지표 열람 초대를 보낸다. 초대받은 사람은 이 초대만으로 작품 열람 권한이나 편집 권한을 얻지 않는다.
3. 작품 대시보드 요청 때 서버가 소유권 또는 현재 초대 상태를 검사한다. public은 작품별 지표를, invited는 초대한 작품 지표를 열람한다.
4. 작가가 공개 범위를 낮추거나 초대를 취소하면 다음 요청부터 접근을 거부한다. 이미 다운로드/열람한 과거 화면까지 회수할 수는 없다.
5. 모든 작가는 별도 작품 권한 없이 공용 컴포넌트의 플랫폼 전체 합계만 본다. 자신의 작품 퍼널에서는 자신이 소유한 목적지의 유입만 상세히 본다.

## 분석 데이터 흐름

```text
웹 리더/내부 UI
    → GA4 이벤트 수집
    → GA4 BigQuery Export (원시 이벤트 저장)
         ↑
작가 대시보드 → 서비스 권한 검사 → 집계 쿼리 → 권한 제한된 결과
```

작가에게 GA4 속성이나 BigQuery 접근 권한을 주지 않는다. **구현 제안:** 현재 범위에서는 서버가 권한을 확인한 뒤 BigQuery에 매개변수화된 집계 조회를 실행해 작가용 화면에 결과를 제공한다. 결과를 서비스 DB에 장기 저장하는 것은 현재 범위가 아니다. 조회 비용과 응답 시간을 관리하기 위한 짧은 캐시는 구현 설계에서 검토한다. BigQuery 이후의 장기 보관·서비스 DB 적재는 후속 기획이다.

**내보내기 권고:** 독서 지표는 실시간 응답이 필요 없으므로 GA4 BigQuery Export의 일일 내보내기를 우선 검토한다. 일반 GA4 속성의 일일 내보내기는 일 100만 이벤트 제한이 있고, BigQuery에는 날짜별 `events_YYYYMMDD` 테이블이 생성된다. 지연 도착 이벤트로 일일 테이블이 이벤트 발생일 이후 최대 3일까지 갱신될 수 있으므로 대시보드에 집계 기준일을 표시하고 최근 날짜를 재처리한다. 예상 이벤트량이 제한에 가까우면 별도 설정을 검토한다.

GA4 속성의 이벤트 수준 보관은 2개월로 설정한다. BigQuery 원시 이벤트 내보내기·보관은 GA4 보관 기간과 별도 관리되며, BigQuery 이후의 장기 보관이나 서비스 DB 적재는 이번 범위에서 결정하지 않는다.

GA4의 BigQuery 스키마는 `user_pseudo_id` 같은 가명 식별자를 제공할 수 있으므로 이를 완전한 익명 데이터로 간주하지 않는다. 본 서비스 사용자 ID·이메일·닉네임과 본문/검색어는 자체 이벤트 매개변수로 보내지 않는다. 24시간 이탈 시도는 가명 브라우저/기기 단위로 추적하고 계정 간 기기를 병합하지 않는다.

## 데이터 모델 영향

GA4 이벤트에는 안정된 작품·회차·페이지·타임라인·에셋·유입 컴포넌트 식별자가 필요하다. 원시 독자 이벤트를 콘텐츠 ID 없이 작품별 지표로 분리할 수 없으므로, 구현 시 데이터 계약에 이 식별자와 분기 관계를 포함한다. 자체 이벤트명은 40자 이하, 이벤트당 매개변수는 25개 이하, 매개변수 이름은 40자 이하, 값은 100자 이하로 제한한다. 이름은 영문자·숫자·밑줄 규칙과 예약어 목록을 검증한다. BigQuery Export의 이벤트 매개변수는 반복 필드이므로 집계 쿼리에서 키를 풀어 읽는다. 위 이벤트명·매개변수는 검토된 계약 초안이며 실제 코드 계측·쿼리는 후속 구현 작업이다.

## 계산·권한 세부 결정

- **표본 단위:** 이탈률 분모는 24시간 판정이 끝난 독서 시도 수다. 하나의 읽기 시도는 GA4 가명 브라우저/기기 식별 범위에서 회차별로 추적하며, 24시간 판정 후 다시 시작한 읽기는 새 시도로 센다. 서로 다른 기기 간에는 시도를 병합하지 않는다.
- **공개 기본값:** `작가만`으로 시작하며, 작가가 명시적으로 선택할 때만 초대 또는 전체 공개한다.
- **백그라운드 시간:** 페이지 속도 계산에서 탭/앱이 백그라운드였던 구간을 제외한다.
- **에셋 충돌:** 여러 설정집 에셋이 같은 표현과 일치하면 독자에게 임의 선택지를 띄우지 않는다. 작성자가 해당 표현에 사용할 에셋을 지정한다. 미지정이면 자동 표시하지 않는다.
- **분기 합류:** 원작 작가에게는 분기를 거쳐 돌아온 유입의 전체 합계만 제공한다. 분기별 유입 상세와 내부 지표는 분기 작가에게 속한다.
