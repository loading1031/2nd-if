# 분기 시스템

> 기획 문서

## 상태: 재기획 (타임라인·길이 규칙 갱신)

## 개요
작가가 허용한 작품에서, 독자가 이미 읽은 타임라인 경계로부터 새로운 스토리라인을 만든다. 분기의 내부 지표는 분기 작가에게 귀속되며, 분기에서 원작으로 돌아오는 유입은 원작 작가의 퍼널에 표시한다.

## 분기 규칙
- 원작 작가는 작품 단위로 2차 창작 허용/비허용을 정한다. 비허용으로 바꾼 뒤에는 새 분기만 막으며 기존 분기는 생성 당시 조건에 따라 유지한다.
- 분기점은 작가가 등록한 타임라인 항목의 경계뿐이다. 타임라인에 등록되지 않은 페이지의 임의 위치에서는 분기할 수 없다.
- 독자는 실제 읽은 타임라인 항목까지만 분기점을 선택할 수 있다.
- 분기별 최대 회차 수는 현재 원작의 전체 회차 수 × 20%를 내림한 값이다. 최소 허용 회차는 없다. 원작 회차 수가 증가하면 각 분기의 상한도 다시 계산되어 증가할 수 있다.
- 이 상한은 분기마다 따로 적용한다.
- 작가 본인이 원작에서 갈라지는 이야기를 만들 때도 `원작` 또는 `외전` 표식으로 구분한다.

## 타임라인 경계와 원작 보존
- 분기 앵커는 타임라인 항목의 안정된 ID에 연결한다.
- 기존 목차/앵커의 구조는 수정하거나 삭제하지 않는다. 관련 세부 내용은 수정할 수 있고 새 항목은 추가할 수 있다.
- 기존 항목을 제거해야 할 경우, 원작자가 분기를 만들고 기존 흐름을 외전으로 보존한다. 원작/외전 전환의 세부 편집 화면은 확인 필요 사항이다.
- 원작자는 분기 내부 내용을 볼 권한을 자동으로 얻지 않는다. 단, 분기에서 원작으로 다시 합류하는 지점은 원작 퍼널에서 분기 경유 유입으로 집계한다.

### 원작 경로 교체 흐름 (구현 제안)

기존 원작 흐름을 더 이상 정본 경로로 이어가지 않으려는 경우, 기존 앵커를 지우거나 다른 ID로 바꾸지 않고 새 원작 경로를 만든다.

1. 원작자가 교체를 시작할 타임라인 앵커를 선택하고, 그 지점부터 이어질 새 경로를 작성한다.
2. 새 경로를 `원작`으로 지정하고 기존 원작의 뒤따르는 흐름은 `외전`으로 지정한다. 전환은 둘 다 저장할 수 있을 때 한 번에 적용해 원작 경로가 잠시 비지 않게 한다. 이 분기도 원작 전체 회차 수의 20% 상한을 적용한다.
3. 기존 회차·페이지·타임라인 ID와 URL은 유지한다. 이전에 그 흐름에서 갈라진 분기 앵커도 유지한다.
4. 독자는 새 원작 경로와 외전을 구분해 선택할 수 있다. 과거 외부 링크는 보존된 외전 콘텐츠로 연결한다.
5. 새 원작 경로의 타임라인은 새 앵커를 추가한다. 이전 앵커는 안정된 원본 기록으로 유지한다.

`원작`/`외전` 역할이 작품·경로·에피소드 중 어디에 저장되는지와 전환 이력은 데이터 설계에서 정한다. 20% 상한을 넘는 새 장편 흐름은 별도 작품으로 시작한다. 외전 경로에서 새 분기를 허용하는지는 확인이 필요하다.

## 길이 상한 계산

| 현재 원작 전체 회차 수 | 각 분기 허용 상한 (내림) |
|---:|---:|
| 2 | 0화 |
| 5 | 1화 |
| 10 | 2화 |
| 50 | 10화 |

분기 생성 자체의 최소 원작 회차 수는 두지 않는다. 상한이 0인 동안에는 분기를 만들어 둘 수 있지만 추가 회차를 발행할 수 없고, 원작 회차가 늘어 상한이 생기면 그 범위에서 이어 쓸 수 있다.

## 분기 방향 설명 (제안, 미확정)
기존 초안은 분기 생성 시 원작과 달라지는 점을 한 줄로 입력하게 했다. 현재 확정된 분기 규칙에는 필수 입력으로 포함되지 않는다.

| 예시 |
|------|
| "캐릭터 A가 살아남는 루트" |
| "빌런 시점에서 다시 보는 이야기" |
| "로맨스 엔딩" |
| "만약 3화에서 다른 선택을 했다면" |

### 기존 분기 방향·유사도 제안
기존 초안은 분기 방향 설명과 AI 유사도 검사로 비슷한 분기를 차단하는 방식을 제안했다. 현재 확정된 분기 규칙에는 포함되지 않았으며, 재도입 여부는 별도 결정이 필요하다.

## 이어쓰기 (미확정)
기존 초안은 타 작가 이어쓰기를 제안했으나, 현재는 허용 여부와 권한 규칙을 확정하지 않았다.

## 관계 모델 개념 (저장소는 기술 검토 필요)

아래 노드와 관계는 제품의 개념 관계를 설명한다. 기존 Neo4j 표기는 현재 구현 선택으로 간주하지 않는다. 저장 구조는 통합 중인 PostgreSQL 모델과 코드를 확인한 뒤 결정한다.

### 노드
- `(:Episode)` — 에피소드 (원작/분기 모두)
- `(:Work)` — 작품

### 관계 (엣지)
- `(:Episode)-[:NEXT]->(:Episode)` — 다음 화 연결
- `(:Episode)-[:BRANCHES_FROM]->(:Episode)` — 분기 원점
- `(:Work)-[:HAS_EPISODE]->(:Episode)` — 작품-에피소드 소속

### 기존 가중치 초안 (재검토 필요)
| 속성 | 타입 | 설명 |
|------|------|------|
| is_original | bool | 원작 경로 여부 |
| visit_count | int | 유효 이동 횟수 (별점 3점 이하 제외) |
| engagement_score | float | = visit_count ([[next-episode-ui]] 참조) |

기존 별점 기반 visit_count/engagement_score는 현재 제품 결정으로 확정되지 않았다. 독서 속도는 페이지별 관찰 지표이며 좋고 나쁨 점수로 해석하지 않는다. 추천 가중치가 필요하면 별도 기획한다.

## 에피소드 목록 표시 (이전 UI 제안)

원작 경로를 기본으로 보여주고, 분기가 있는 화에 배지로 표시:

```
[원작]
1화: 시작
2화: 전개          [분기 2개 ▼]  ← 클릭하면 펼침
  └ "A 생존 루트" by 작가A (3화)
  └ "로맨스 엔딩" by 작가B (2화)
3화: 반전
4화: 결말          [분기 1개 ▼]
  └ "빌런 시점" by 작가C (1화)
5화: 에필로그
```

- 기본은 원작 경로만 표시 (깔끔한 읽기 경험)
- 분기 있는 화에 배지 + 아코디언으로 펼침
- 분기 정보: 방향 설명, 작가, 에피소드 수

## 분기 생성 플로우
1. 독자가 분기 허용 작품의 타임라인 항목을 읽음
2. 해당 타임라인 경계가 읽은 범위 안에 있고 현재 분기 상한이 남았는지 확인
3. "여기서 분기하기" 버튼 클릭
4. 분기를 생성하고 해당 타임라인 항목 ID에 연결
5. 원작의 기존 문맥을 어떻게 제공할지는 별도 설계
6. 분기 작가가 에피소드를 작성
7. 원작 회차 수가 늘면 각 분기의 회차 상한을 다시 계산

## 분석 지표
- 분기 내 페이지·회차 행동은 분기 작가의 분석 권한으로 관리한다.
- 분기에서 원작 흐름으로 돌아오는 합류 이벤트는 원작의 퍼널에서 분기 경유 유입으로 집계한다.
- 이벤트 수집과 작가 지표 권한은 [작가 인사이트](author-insights.md)를 따른다.
