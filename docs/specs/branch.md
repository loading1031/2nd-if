# 분기 시스템

> 기획 문서

## 상태: 기획 중

## 개요
독자/2차 창작자가 원작의 특정 에피소드 지점에서 새로운 스토리라인을 분기하는 핵심 기능.

## 분기 규칙
1. **20화 제한**: 원작의 최신화로부터 20화 이전의 에피소드에서만 분기 가능
   - 예: 원작이 50화까지 연재 → 30화 이전에서만 분기 가능
   - 원작 보호 및 스포일러 방지 목적
2. **라이선스 준수**: 원작의 [[license]] 설정에 따라 분기 가능 여부 결정
3. **분기점 노출**: 해당 에피소드까지 읽은 독자에게만 분기점 표시 (스포일러 방지)

## 그래프 구조 (Neo4j)

### 노드
- `(:Episode)` — 에피소드 (원작/분기 모두)
- `(:Work)` — 작품

### 관계 (엣지)
- `(:Episode)-[:NEXT]->(:Episode)` — 다음 화 연결
- `(:Episode)-[:BRANCHES_FROM]->(:Episode)` — 분기 원점
- `(:Work)-[:HAS_EPISODE]->(:Episode)` — 작품-에피소드 소속

### 엣지 속성 (NEXT 관계)
| 속성 | 타입 | 설명 |
|------|------|------|
| is_original | bool | 원작 경로 여부 |
| like_count | int | 좋아요 수 |
| visit_count | int | 이 경로로 이동한 횟수 |
| engagement_score | float | 가중치 (like_count + visit_count 기반 계산) |

## 분기 생성 플로우
1. 독자가 에피소드 N화를 읽음
2. 분기 가능 조건 확인 (20화 제한, 라이선스)
3. "여기서 분기하기" 버튼 클릭
4. editor.js로 새 에피소드 작성
5. Neo4j에 `BRANCHES_FROM` 관계 생성
6. 이후 해당 분기에서 계속 연재 가능

## 가중치 업데이트
- 독자가 "다음 화"에서 특정 경로를 선택할 때마다 해당 `NEXT` 엣지의 `visit_count` +1
- 좋아요 클릭 시 `like_count` +1
- `engagement_score` = 가중치 계산 공식 (추후 확정)

## 의존성

- [[license]] — 분기 허용 여부 결정
- [[next-episode-ui]] — 분기된 다음 화를 가중치 순으로 표시
- [[auth]] — 분기 생성자 인증
