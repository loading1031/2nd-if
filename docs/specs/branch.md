# 분기 시스템

> 기획 문서

## 상태: 기획 완료

## 개요
독자/2차 창작자가 원작의 특정 에피소드 지점에서 새로운 스토리라인을 분기하는 핵심 기능.
밈처럼 퍼지되, 같은 방향의 분기는 선착순으로 제한하여 다양성과 경쟁을 유도한다.

## 분기 규칙
1. **20화 제한**: 원작의 최신화로부터 20화 이전의 에피소드에서만 분기 가능
   - 예: 원작이 50화까지 연재 → 30화 이전에서만 분기 가능
   - 원작 보호 및 스포일러 방지 목적
2. **라이선스 준수**: 원작의 [[license]] 설정에 따라 분기 가능 여부 결정
3. **분기점 노출**: 해당 에피소드까지 읽은 독자에게만 분기점 표시 (스포일러 방지)
4. **유사 분기 제한 (선착순)**: 같은 에피소드에서 비슷한 방향의 분기는 차단
   - 분기 생성 시 "방향" 설명 필수 입력
   - AI가 기존 분기들과 유사도 검사
   - 유사도 높으면 → 기존 분기 이어쓰기 유도 또는 차단
   - 유사도 낮으면 → 새 분기 생성 허용

## 분기 방향 (direction)
분기 생성 시 작가가 입력하는 한 줄 설명. 이 분기가 원작과 어떻게 달라지는지를 나타냄.

| 예시 |
|------|
| "캐릭터 A가 살아남는 루트" |
| "빌런 시점에서 다시 보는 이야기" |
| "로맨스 엔딩" |
| "만약 3화에서 다른 선택을 했다면" |

### AI 유사도 검사
- 새 분기의 방향 설명을 기존 분기들과 비교
- 같은 에피소드에서 분기된 것들만 비교 대상
- 유사도 기준 초과 시 → "이미 비슷한 분기가 있습니다: [기존 분기 제목]" 안내
- Dify Chatflow 또는 임베딩 유사도로 구현

## 이어쓰기
- 기존 분기에 다른 작가가 이어서 에피소드를 추가할 수 있음
- 분기 최초 작가의 허용 설정에 따라 결정 (열린 분기 / 닫힌 분기)
- 이어쓰기도 별점/가중치 시스템 적용

## 그래프 구조 (Neo4j)

### 노드
- `(:Episode)` — 에피소드 (원작/분기 모두)
- `(:Work)` — 작품

### 관계 (엣지)
- `(:Episode)-[:NEXT]->(:Episode)` — 다음 화 연결
- `(:Episode)-[:BRANCHES_FROM]->(:Episode)` — 분기 원점
- `(:Work)-[:HAS_EPISODE]->(:Episode)` — 작품-에피소드 소속

### 엣지 속성 (NEXT 관계)
| 속성 | 타입 | 설명 |
|------|------|------|
| is_original | bool | 원작 경로 여부 |
| visit_count | int | 유효 이동 횟수 (별점 3점 이하 제외) |
| engagement_score | float | = visit_count ([[next-episode-ui]] 참조) |

## 에피소드 목록 표시

원작 경로를 기본으로 보여주고, 분기가 있는 화에 배지로 표시:

```
[원작]
1화: 시작
2화: 전개          [분기 2개 ▼]  ← 클릭하면 펼침
  └ "A 생존 루트" by 작가A (3화)
  └ "로맨스 엔딩" by 작가B (2화)
3화: 반전
4화: 결말          [분기 1개 ▼]
  └ "빌런 시점" by 작가C (1화)
5화: 에필로그
```

- 기본은 원작 경로만 표시 (깔끔한 읽기 경험)
- 분기 있는 화에 배지 + 아코디언으로 펼침
- 분기 정보: 방향 설명, 작가, 에피소드 수

## 분기 생성 플로우
1. 독자가 에피소드 N화를 읽음
2. 분기 가능 조건 확인 (20화 제한, 라이선스)
3. "여기서 분기하기" 버튼 클릭
4. **분기 방향 입력** (한 줄 설명, 필수)
5. **AI 유사도 검사** → 통과 시 진행, 유사 시 기존 분기 안내
6. TipTap 에디터로 새 에피소드 작성
7. Neo4j에 `BRANCHES_FROM` 관계 생성
8. 이후 해당 분기에서 계속 연재 가능 (이어쓰기 포함)

## 가중치 업데이트
- 독자가 A→B 경로로 이동 시:
  - B의 별점이 3점 이하 → visit_count 증가하지 않음
  - B의 별점 미등록 또는 4점 이상 → visit_count +1
- `engagement_score` = `visit_count` ([[next-episode-ui]] 참조)
