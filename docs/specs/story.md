# 작품/에피소드 시스템

> 기획 문서

## 상태: 재기획 (페이지·타임라인 구조 반영)

## 개요
원작자가 작품을 생성하고, 에피소드(화) 단위로 연재하는 시스템.

## 데이터 구조

### 작품 (Work)
| 필드 | 타입 | 필수 | 비고 |
|------|------|------|------|
| title | string | O | 작품 제목 |
| description | text | X | 작품 소개 |
| author | User | O | 원작자 |
| derivative_allowed | bool | O | 작가가 선택하는 2차 창작 허용 여부. 상세 권한은 [[license]] 참조 |
| created_at | datetime | O | |
| status | enum | O | 연재중, 완결, 중단 |

### 에피소드 (Episode)
| 필드 | 타입 | 필수 | 비고 |
|------|------|------|------|
| work | Work | O | 소속 작품 |
| episode_number | int | O | 화 번호 |
| title | string | O | 에피소드 제목 |
| pages | ordered list[Page] | O | 글자 수 제한이 있는 작성 페이지 목록 |
| author | User | O | 작성자 |
| created_at | datetime | O | |
| is_paid / price | future extension | — | 현재 유료 열람과 결제는 범위 밖 ([[revenue]] 참조) |
| view_count | int | O | 기존 기본 조회 카운터. 새 독서 인사이트 기준은 [작가 인사이트](author-insights.md)의 GA4/BigQuery 흐름 |
| avg_rating | float | X | 별점 평균 (1~5), null=미등록 |
| rating_count | int | O | 별점 등록 수, default=0 |
| branch_direction | string | X | 기존 제안이며 현재 확정 범위가 아님 ([[branch]] 참조) |

> 작품 간 원작/분기 관계는 [[branch]]의 개념 규칙을 따른다. 저장 필드와 관계 모델은 현재 구현 코드를 확인한 뒤 확정한다. 기존 Neo4j 전제를 구현 결정으로 취급하지 않는다.

### 원작/외전 구분

- 작품을 쓴 사람이 원작자와 같은 사람인지와 별개로, 원작자가 만든 경로에도 `원작` 또는 `외전` 역할을 표시할 수 있어야 한다.
- 원작 경로 교체 시 새 경로는 원작으로 표시하고, 밀려난 기존 흐름은 삭제하지 않고 외전으로 보존한다.
- 분기 관계와 원작/외전 역할은 서로 다른 정보다. 이 구분을 작품, 경로 또는 에피소드 묶음 중 어디에 저장할지는 구현 데이터 모델에서 정한다. 관련 흐름은 [[branch]]를 따른다.

## 페이지와 읽기 타임라인

- 작가는 에피소드를 페이지 단위로 나눠 작성한다. 페이지별 글자 수 제한은 필요하지만 구체 한도는 아직 정하지 않았다.
- 모바일 리더는 작성 페이지 순서대로 이동한다. 웹 리더는 같은 콘텐츠를 더 큰 글자와 넓은 레이아웃으로 표시한다.
- 작가는 페이지 또는 장면을 목차/타임라인 항목으로 등록할 수 있다. 등록되지 않은 임의 페이지 위치에서는 분기할 수 없다.
- 기존 타임라인 항목의 앵커는 수정·삭제할 수 없고, 항목의 세부 정보는 수정할 수 있다. 새 항목은 추가할 수 있다.
- 독자는 자신이 실제로 읽은 타임라인 항목까지만 타임라인을 보고 분기점을 선택할 수 있다.
- 독서 지표 기준은 [작가 인사이트](author-insights.md)를 따른다.

### 타임라인 항목 (요구사항)

| 정보 | 독자 표시 | 편집 규칙 |
|---|---|---|
| 고정 앵커/목차 위치 | 읽은 범위만 노출 | 기존 항목 변경·삭제 불가, 추가 가능 |
| 장면/목차 설명 | 작가 선택에 따라 노출 | 세부 내용 수정 가능 |
| 연결 페이지 | 읽기·분기 기준점 | 분기는 등록된 타임라인 항목만 허용 |

## 저장 위치
- Work, Episode 메타데이터: Django ORM (PostgreSQL)
- 원작·분기 관계: 저장 구조 검토 필요. 최신 Django/PostgreSQL 코드와 일치시킨다.

## 사용자 플로우

### 작품 - 정상
1. 원작자: 작품 생성 (제목 + 소개 + 2차 창작 허용 여부) → 작품 상세 페이지로 이동
2. 독자: 작품 목록 → 검색 → 작품 선택
3. 독자: 작품 상세 → 에피소드 목록 확인

### 작품 - 에러
4. 제목 없이 작품 생성 → 에러
5. 비로그인 상태에서 작품 생성 → 로그인 페이지로 리다이렉트
6. 존재하지 않는 작품 접근 → 404

### 에피소드 - 정상
7. 원작자: 에피소드 작성 → 발행 → 에피소드 읽기 페이지로 이동
8. 독자: 에피소드 읽기 → 조회수 +1
9. 독자: 별점 등록 (1~5) → 평균 별점 갱신
10. 독자: 별점 수정 → 기존 별점 업데이트

### 에피소드 - 에러
11. 비로그인 상태에서 에피소드 작성 → 로그인 페이지로 리다이렉트
12. 비로그인 상태에서 별점 등록 → 로그인 필요
13. 별점 범위 초과 (0, 6 등) → 400 에러
14. 존재하지 않는 에피소드 접근 → 404

### 검색/필터
15. 작품 목록에서 제목 검색 → 필터링된 결과
16. 작품 목록에서 상태 필터 (연재중/완결) → 필터링된 결과
17. 검색 결과 없음 → 빈 상태 표시

### 작품별 포인트 풀 (현재 범위 밖)
| 필드 | 타입 | 필수 | 비고 |
|------|------|------|------|
| work | Work | O | 소속 작품 |
| point_pool | int | O | 현재 사용 가능한 포인트 풀, default=0 |
| updated_at | datetime | O | 마지막 풀 갱신 시점 |

> 기존 수익·보상 제안이며 현 제품 재기획에서 범위와 우선순위를 다시 확인한다 ([[point-system]] 참조).
