# /scenario — 사용자 흐름과 테스트

먼저 `.claude/rules/docs.md`, `.claude/rules/django.md`, `.claude/rules/workflow.md`를 읽는다.

`/scenario <이슈 번호 또는 주제>`:

1. 관련 이슈·스펙·기존 구현과 테스트를 읽는다. 스펙이 없어도 이슈의 완료 기준으로 충분하면 별도 문서 없이 진행한다.
2. 정상·오류·권한·경계 흐름에서 실제 구현할 동작만 테스트로 도출한다. 아직 결정되지 않은 제품 동작을 테스트로 확정하지 않는다.
3. 기존 테스트·fixture를 재사용하고 중복 테스트는 만들지 않는다. 필요하면 기존 테스트나 conftest를 수정한다.
4. async DB 테스트는 기존 pytest 설정과 transaction 패턴을 따른다. E2E는 실제 브라우저 경로와 실행 환경이 있을 때 작성한다.
5. 관련 테스트를 실행한다. 구현 전의 의도된 실패와 환경 오류·크래시를 구분하고, 실제 실행 결과만 보고한다.
6. 테스트 범위·결과·남은 일을 이슈에 기록한다. 테스트 작성 자체가 커밋·병합·워크트리 삭제 권한을 뜻하지 않는다.

별도 위임 요청이 없으면 메인 에이전트가 순차 수행한다. 생성할 테스트 수나 에이전트 수를 미리 강제하지 않는다.
