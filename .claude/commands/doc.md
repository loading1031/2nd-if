# /doc — 기획 문서 관리

`docs/` Obsidian 볼트에 문서를 생성하거나 업데이트한다.

## 사용법

```
/doc spec {이름}    — 기획 문서 생성 (docs/specs/)
/doc design {이름}  — 디자인 문서 생성 (docs/design/)
/doc dev {이름}     — 개발 문서 생성 (docs/dev/)
/doc check          — 전체 문서 의존성 충돌 검사 (lint)
/doc status         — 전체 문서 상태 요약
/doc log            — 최근 문서 작업 이력 표시
```

## 참조 파일
- 문서 컨벤션: `.claude/rules/docs.md`
- 문서 템플릿: `.claude/rules/docs.md`의 "문서 템플릿" 섹션
- 기획 인덱스: `docs/specs/index.md`
- 기획 문서: `docs/specs/{이름}.md`
- 디자인 문서: `docs/design/design-{이름}.md`
- 개발 문서: `docs/dev/dev-{이름}.md`

## 실행 절차

### spec (기획 문서)
1. `docs/specs/{이름}.md` 생성
2. `.claude/rules/docs.md`의 기획 템플릿 적용
3. `docs/specs/index.md`에 링크 추가
4. 기존 기획 문서와 충돌 여부 확인

**에러 처리:**
- `docs/specs/` 디렉토리가 없으면 생성
- 동일 이름 파일이 이미 존재하면 사용자에게 덮어쓸지 확인

### design (디자인 문서)
1. 사용자에게 어떤 기획(`specs/`)에 연결할지 확인
2. **기획 문서 존재 확인**: `docs/specs/{기획이름}.md`가 없으면 사용자에게 알리고 먼저 생성할지 확인
3. `docs/design/design-{이름}.md` 생성
4. `.claude/rules/docs.md`의 디자인 템플릿 적용 — `## 기획` 섹션에 `[[기획문서]]` 링크
5. 해당 기획 문서의 `## 디자인 문서` 섹션에 역링크 추가
6. 패턴 라이브러리 템플릿도 함께 생성할지 확인

### dev (개발 문서)
1. 사용자에게 어떤 디자인(`design/`)에 연결할지 확인
2. **디자인 문서 존재 확인**: `docs/design/design-{디자인이름}.md`가 없으면 사용자에게 알리고 먼저 생성할지 확인
3. `docs/dev/dev-{이름}.md` 생성
4. `.claude/rules/docs.md`의 개발 템플릿 적용 — `## 디자인`, `## 기획` 섹션에 링크
5. 해당 디자인 문서의 `## 개발` 섹션에 역링크 추가

### 병렬 문서 생성

같은 기획에 대해 design + dev 문서를 동시에 생성해야 하는 경우:

1. **메인 에이전트**: 기획 문서 읽기 + 디자인/개발 문서 요구사항 정리
2. **병렬 에이전트 실행** (각 에이전트는 새 파일 생성만):
   - **Design 에이전트** (worktree): `docs/design/design-{이름}.md` 생성
   - **Dev 에이전트** (worktree): `docs/dev/dev-{이름}.md` 생성
3. **후처리** (메인 에이전트): 순차 병합 후 역링크 업데이트
   - 기획 문서에 `## 디자인 문서` 역링크 추가
   - 디자인 문서에 `## 개발` 역링크 추가
   - `docs/specs/index.md` 갱신

**주의**: 에이전트는 새 파일 생성만 허용. 기존 파일(기획 문서, index.md)의 역링크 추가는 메인 에이전트가 후처리로 수행.

### check (충돌 검사)

Explore 에이전트에 위임하여 효율적으로 검사:

1. **에이전트에 전달할 정보**:
   - 검사 대상 디렉토리: `docs/specs/`, `docs/design/`, `docs/dev/`
   - 검사 규칙: `.claude/rules/docs.md`의 "충돌 감지 규칙"
2. **에이전트 수행 내용**:
   - `docs/` 내 모든 .md 파일을 읽음
   - 모든 `[[링크]]`를 추출
   - 각 링크 대상 파일이 존재하는지 확인 (깨진 링크)
   - 링크된 문서 간 상태/내용 충돌 확인:
     - 기획이 변경되었는데 디자인이 반영 안 된 경우
     - 디자인이 변경되었는데 개발이 반영 안 된 경우
     - 필드 정의 불일치
3. **결과 보고 형식**:
   ```
   ## 깨진 링크
   - design-signup-page.md → [[auth-v2]] (파일 없음)

   ## 상태 불일치
   - auth.md (기획 완료) → design-signup-page.md (상태 없음)

   ## 역링크 누락
   - dev-auth-signup.md가 design-signup-page.md를 참조하지만, design-signup-page.md에 역링크 없음
   ```

**에러 처리:**
- `docs/` 디렉토리가 비어있으면 "문서가 없습니다" 보고
- 링크 대상이 존재하지 않으면 깨진 링크 목록에 추가 (중단하지 않음)

### status (상태 요약)

Explore 에이전트에 위임:

1. `docs/` 내 모든 .md 파일의 `## 상태:` 행을 읽음
2. 계층별로 그룹핑하여 표 형태로 출력:
   ```
   | 문서 | 계층 | 상태 |
   |------|------|------|
   | auth | 기획 | 기획 완료 |
   | design-signup-page | 디자인 | 디자인 완료 |
   | dev-auth-signup | 개발 | 미구현 |
   ```
3. 요약 통계 추가:
   ```
   기획: 5건 (기획 완료 4, 진행중 1)
   디자인: 3건 (디자인 완료 2, 미작성 1)
   개발: 2건 (구현 완료 1, 미구현 1)
   ```

### log (작업 이력)

`docs/log.md`의 최근 10항목을 표시한다.

### 자동 로그 기록 (LLM Wiki 패턴)

**모든 /doc 명령 실행 후** `docs/log.md`에 항목을 자동 추가:

```markdown
## {날짜} {작업유형} | {제목}
- {변경 내용 1줄씩}
```

작업 유형:
- `ingest` — 새 문서 생성 또는 대규모 업데이트
- `update` — 기존 문서 소규모 수정
- `lint` — check 실행 후 발견된 이슈 + 수정 내역
- `query` — status 실행

### 자동 index 갱신

문서 생성/삭제 시 `docs/specs/index.md`를 자동 갱신:
1. `docs/specs/` 내 모든 .md 파일 스캔 (index.md 제외)
2. 각 파일의 첫 번째 `# 제목` 행에서 설명 추출
3. 기존 카테고리 구조 유지, 새 문서는 적절한 카테고리에 추가
4. 카테고리에 맞지 않으면 사용자에게 확인

## 규칙
- 파일명: kebab-case
- 기획은 접두어 없음, 디자인은 `design-`, 개발은 `dev-`
- `[[위키링크]]`는 파일명만 사용 (경로 제외)
- 문서 생성/수정 시 항상 역링크도 함께 업데이트
- 문서 생성/수정 후 반드시 `docs/log.md`에 이력 기록
- 충돌 발견 시 즉시 사용자에게 알림
- 병렬 에이전트는 새 파일 생성만 허용, 기존 파일 수정은 메인 에이전트가 후처리
- 워크트리 병합 후 즉시 정리 (`git worktree remove`)
