# /doc — 주제별 스펙

먼저 `.claude/rules/docs.md`와 `.claude/rules/workflow.md`를 읽는다.

- `/doc spec <주제>`: 관련 이슈와 기존 스펙을 읽고 결정·요구사항·사용자 흐름·완료 기준을 반영한다. 하나의 스펙으로 충분하면 문서를 분리하지 않는다.
- `/doc design <주제>`: 별도 시각 명세가 필요한 경우에만 작성한다. 기존 컴포넌트와 스타일 규칙을 확인한다.
- `/doc dev <주제>`: 운영·배포 가이드가 필요한 경우 작성한다. 코드 파일 목록을 반복하는 문서는 만들지 않는다.
- `/doc check [주제]`: 해당 이슈와 관련 문서·구현을 대조해 용어·수치·완료 상태·깨진 링크를 보고한다. 전체 역링크 검사를 하지 않는다.

작업 상태와 다음 행동은 이슈에 남긴다. 백로그·로그·작업지시서 파일은 중복 생성하지 않는다. 커밋은 요청 범위에 포함된 경우 `/commit` 규칙을 따른다.
