# /merge — 검토 후 통합

먼저 `.claude/rules/workflow.md`를 읽는다.

- `/merge check`: 관련 이슈, PR, 커밋 차이, 실제 워크트리 경로, 미커밋 변경과 중복 커밋을 확인한다. 검사만 요청되면 병합하지 않는다.
- `/merge`: 승인된 대상만 검토·검증한 뒤 PR base `dev`로 통합한다. 릴리스만 `dev` → `main`이다. 단순한 계속 요청으로 운영 배포를 시작하지 않는다.
- `/merge css`: CSS 변경이 있을 때 기존 빌드 도구·명령을 확인해 빌드한다. 바이너리 설치나 변경 없는 빌드를 강제하지 않는다.
- 과거 `backlinks` 옵션은 더 이상 역링크를 생성하지 않고 `/doc check`의 관련 문서 정합성 확인으로 안내한다.

브랜치 전체를 무조건 합치지 않는다. 충돌은 동작·순서·권한을 검토한다. 기존 코드와 URL·설정 모두를 무조건 합집합으로 합치지 않는다. 해소할 수 없는 제품 선택은 사용자에게 묻는다.

정리는 실제 `git worktree list` 경로와 보존·통합 상태를 확인한 뒤에만 한다. 일반 worktree remove와 branch -d를 사용하며 강제 삭제나 원격 브랜치 삭제는 하지 않는다. 관련 스펙을 필요한 만큼만 수정하고 이슈에 PR·검증·남은 일을 기록한다.
