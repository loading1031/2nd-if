# /feature — 이슈 기반 기능 구현

먼저 `.claude/rules/CLAUDE.md`, `.claude/rules/docs.md`, `.claude/rules/workflow.md`를 읽는다.

`/feature <이슈 번호 또는 주제> [docs|design|test|feat|status]`를 지원한다.

1. 이슈의 목표·완료 기준·다음 행동과 관련 스펙, 기존 WIP를 확인한다. 불명확한 요구만 질문한다.
2. `status`는 이슈·커밋·실제 구현을 대조해 보고하고 파일을 바꾸지 않는다.
3. 필요한 요구사항은 기존 스펙 한 곳에 정리한다. 기획·디자인·개발 문서 세 벌 생성을 전제하지 않는다.
4. UI 작업이면 사용자 흐름·상태·기존 컴포넌트를 확인한다. 디자인 명세는 독립적으로 필요한 경우에만 작성한다.
5. 동작 변경은 정상·오류·권한 사례를 테스트로 확인하고 구현한다. 작은 문구·스타일 수정에 동작을 복제한 테스트를 추가하지 않는다.
6. 해당 기술 규칙을 읽고 필요한 검증을 실행한다. 마이그레이션은 생성·검토와 적용 환경을 구분하고 운영 DB에 자동 적용하지 않는다.
7. 결과·검증·남은 일을 이슈에 기록한다. 커밋은 `/commit`, 통합은 `/merge` 규칙과 사용자 승인 범위를 따른다.

이전 결과에 의존하는 문서·UI·구현을 병렬로 진행하지 않는다. 별도 위임 요청이 없으면 메인 에이전트가 순차 수행한다. 요청된 하위 작업만 수행할 수 있으며 이전 단계의 완료를 추정하지 않는다.
